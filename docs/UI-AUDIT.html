Findings and fixes

  1. Native hover popups

    Replaced browser/WebView title tooltips with one compact tooltip surface: 350ms hover delay, light/dark tokens, viewport flipping and clamping, pointer-events:none, keyboard descriptions, and dismissal on leave, click, scroll, Escape, resize, blur, or trigger removal. Modal tooltips stay in the active dialog. A compatibility guard migrates late native titles.

  2. Verbose or redundant tooltip copy

    Shortened Mode, Autonomy, Effort and retry descriptions. Removed the repeated session-title and line-count hover text; kept the line-count accessible name. File paths, provider URLs, inspector facts, commit subjects and source URLs only show full-text tooltips when truncated. Inspector tab hints appear only when their visible labels are hidden.

  3. Cramped Settings rows

    Settings now responds to the actual center-pane width, not only the whole window. Provider rows reflow; labels stack where needed; the panel preview stays within its row. Reproduced before: 372px of content in a 340px view, a 0px provider URL and an 82px key field. Checked after: zero horizontal overflow, a 250px URL and a 168px key field at 940×600 with Code open.

  4. Settings click interception

    A scrolled Add provider button previously overlapped the floating inspector toggle by 9px, and a hit test reached the toggle instead of the button. Settings now reserves the corner gutter. The same hit test passes with 23px clearance.

  5. Composer spacing and long labels

    Effort and attachment actions retain their size while a long model name truncates before the microphone/send controls collide. File chips cannot exceed the composer width. Narrow Settings effort chips use compact, consistent padding and stay on one row in the tested minimum-width layout.

  6. Clipped picker popups

    Mode, model, effort, autonomy and folder pickers use the top layer, or a portal fallback. Each menu is measured, flipped, height-limited and clamped to the viewport rather than clipped by a scrolling Settings panel. Outside scrolling, resizing and DOM removal dismiss it; keyboard arrows can open it without jumping the scroll position.

  7. Narrow Code inspector

    The file tree now shares available width instead of always claiming 200px. It ranges from 112px to 200px with a 35% share, leaving a readable editor. The populated browser fixture checks at least 120px of editable text width. The empty state has explicit readable insets.

  8. Keyboard inspector controls

    Tabs now support Left/Right, Home/End and roving focus, with named tab panels. The Code separator supports arrow-key resizing, Home/End, an accessible current/min/max width, and its existing pointer reset behavior.

  9. Dialog and menu containment

    Provider fields scroll while the dialog footer stays available. Unsaved/About bodies have scroll containment for long content. Titlebar menus are capped to available window height, and their active keyboard row scrolls into view. Existing scrollable output, skills and help views are preserved.

  10. Recent UI fixes preserved

    The original 16 assertions still pass: value-only Mode/Autonomy/Effort labels and accessible names, inspector tabs before session selection, sidebar title/chevron alignment and insets, balanced File menu padding, View checkbox gutters, and chat clearance from the inspector toggle.

Scope and limits

The browser serves the actual desktop/ui/ HTML/CSS/JS with synthetic Tauri IPC. Populated fixtures include prose, code, edit diffs, skills, files, GitHub changes and statistics. They prove frontend presentation and interaction, not native WebView behavior, real files/Git/providers, streaming, packaging or an installed release. Both color schemes were checked on a flat background; generated artwork was not part of the fixture. Native window minimum width is 940px; smaller mobile fallback rules were not part of this matrix.

JavaScript correctness lint and CSS lint passed. Full Rust workspace check/test/Clippy results are recorded in the linked PR and its CI run; the local machine lacks GTK development libraries and the pinned Rust toolchain, so those local attempts were environment-blocked. CI uses the repository release workflow's Rust 1.100.0 and installs desktop system libraries.

Audit baseline: main commit c341c19, including UI fixes from #28 and #30. Reproduce with PORT=4187 node desktop/tests/serve.mjs and /?test&audit&rich; append &scheme=dark for dark appearance. The test README contains syntax and lint commands.
